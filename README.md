# GPS distance QA: find it, prove it, fix it, lock it

> **All data in this repository is SYNTHETIC**, generated by `DataGenerator` from a fixed seed.
> It uses the fictional assessment case (vehicle advertising, pay per km inside a zone). No real drivers, advertisers, locations or employer data.

## Run it (about 1 minute)

Needs **Java 17+** and **Maven**.

```
run.bat          (Windows)
./run.sh         (Mac / Linux)
```

This will:
1. run the regression tests (`mvn test`),
2. generate `data/pings_SYNTHETIC.csv` (3,070 pings),
3. run the QA tool, print the findings and write **`reports/qa_report.html`**.

Each push also runs this on GitHub Actions (see the **Actions** tab). The run summary shows the regression matrix and the tool output.

## What is in here

| Path | What it is |
|---|---|
| `src/main/java/qa/DataGenerator.java` | Synthetic data with known faults, plus an answer key and the true km |
| `src/main/java/qa/LegacyCalculator.java` | **v1**: the calculation that gets distance wrong (kept unchanged) |
| `src/main/java/qa/DistanceEngine.java` | **v2**: the corrected reference implementation. Each fix can be switched off |
| `src/main/java/qa/QaChecker.java` | **The QA tool**: data checks, root-cause waterfall, before/after, answer key, regression matrix, HTML report |
| `src/main/java/qa/Scenarios.java` | Small hand-checkable cases, one per rule |
| `src/test/java/qa/RegressionTest.java` | Regression check: v2 passes, v1 fails, v2-minus-that-fix fails |
| `src/test/java/qa/DatasetTest.java` | End-to-end: v2 matches the true km, v1 doesn't, v2 rejects exactly the faulty pings |
| `data/` | Generated dataset, fault labels, ground truth (all SYNTHETIC) |
| `reports/` | Generated report and CSVs |

## Rules implemented (from the brief)

- A ping >100 m off the road, or implying >150 km/h, is GPS noise and is ignored. Speed is measured against the **last valid** ping.
- Duplicates (same driver, same timestamp) count once; the first one received is kept.
- Late / out-of-order pings are placed by their own timestamp.
- Timestamps are UTC; the daily report is cut at 00:00 UTC+9, and segments crossing local midnight are split.
- Only distance inside the zone counts; segments crossing the zone edge are clipped.

Interpretations and assumptions are in `intent.md` / `directive.md`.
